### 1.4 How path-scoped rules load (verified, not assumed)

Source: Claude Code docs, "How Claude remembers your project", `https://code.claude.com/docs/en/memory`, fetched in this run.

- "A path-scoped rule loads when Claude uses the Read, Write, or Edit tool on a matching file. It also loads when Claude views a matching file with a Bash command that counts as a read". Supports: a rule's glob is its only activation condition.
- "`paths` is the only field Claude Code reads from a rule; any other field is ignored without an error." Supports: the loader cannot see `engine.name`; no glob can express "Custom only".
- Pattern table: "`src/components/*.tsx` | `.tsx` files directly in the base directory's `src/components/`, not in subfolders"; "`*.md` | `.md` files anywhere under the base directory"; "`/*.md` | `.md` files directly in the base directory, not in subfolders". Supports: `*` does not cross `/` (so `fnmatch` in `test_engine_support.py:29` is wrong, E3); a bare filename pattern such as `CMakePresets.json` matches at any depth; a leading `/` anchors to the root.
- "if two instructions contradict each other, Claude may pick one arbitrarily." Supports: C5 and D2 are behavioural defects, not wording.
- On-demand rules over a per-file limit are truncated: "200K context window: 40,000 characters". The largest rule is `engine-code.md` at 9,196 bytes; no rule is near the limit.
